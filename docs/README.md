# docs/ — Project knowledge base

Everything in this folder is generated by `/onboard` (and refined by later sessions). It is the agent's long-term memory: fresh sessions rely on these files, never on chat history. Until onboarding runs, this folder contains only READMEs.

## What onboarding generates

```
docs/
├── constitution.md        Non-negotiable project principles, semver-versioned articles.
│                          Read before any significant decision.
├── product/
│   ├── brief.md           Vision paragraph + full Lean Canvas (problem, segments, UVP,
│   │                      channels, revenue, costs, metrics, unfair advantage).
│   ├── prd.md             Product requirements: EARS functional requirements (FR-001…),
│   │                      NFRs (NFR-001…), non-goals, success metrics, clarifications log.
│   ├── personas.md        1-3 personas: day-in-the-life, trigger moment, success moment.
│   └── roadmap.md         Phases: v0.1 walking skeleton → v1 → post-launch, with feature
│                          ids matching features.json and exit criteria per phase.
├── design/
│   ├── DESIGN.md          The 10-section design system. Law for all UI work.
│   ├── voice.md           Tone of voice: persona, vocabulary, UX-writing patterns.
│   │                      Law for all user-facing copy.
│   └── tokens.css         Design tokens (web), or the platform equivalent for native
│                          (e.g. DesignTokens.swift inside apps/<id>/).
├── tech/
│   ├── tech-stack.md      Chosen stack with versions and reasons; links to ADRs.
│   ├── architecture.md    System context, modules, data flow, state, sync/offline,
│   │                      error handling, security notes.
│   ├── structure.md       Repo + per-component folder maps, placement rules.
│   └── testing.md         Test pyramid for agents, evidence/ conventions,
│                          deterministic-mode requirements.
└── adr/
    └── NNNN-title.md      Architecture Decision Records (MADR-lite). See adr/README.md.
```

## Rules

- **Docs are living.** When reality changes — code, decisions, scope — update the affected doc in the same session. A stale doc is worse than no doc, because agents trust it.
- **`constitution.md` is special:** any change requires explicit user approval and a version bump, following the amendment procedure written inside it.
- **No duplication.** Each fact lives in exactly one doc; other docs link to it.
- **These files are instances**, generated from `templates/docs/*`. When updating an instance, never edit the template — and vice versa.
- **Read on demand.** The doc map in `CLAUDE.md` says when to read what; do not bulk-load this folder into context.
